Low Level Design (LLD)

Live Trading Simulation System (ATR + Market Regime Engine)


---

1. Overview

The system is a lightweight real-time trading simulator written in C++.
It continuously fetches market prices from Yahoo Finance, computes technical indicators, classifies market conditions, generates trading signals, and simulates trade execution with risk management.

The architecture is modular and composed of:

Market Data Layer

Indicator Engine

Feature Engine

Signal Engine

Risk Management

Trade Execution Simulator

Portfolio Tracking



---

2. System Goals

Functional Goals

Fetch live market price data

Compute SMA indicators

Compute ATR-based volatility

Detect market regime

Generate buy/sell signals

Simulate order execution

Apply risk management

Track portfolio equity


Non-Functional Goals

Low memory footprint

O(1) indicator updates

Modular architecture

Easy feature extension

Real-time loop execution

4.3 ATR Module

Class

class ATR


---

Responsibility

Computes Average True Range (ATR) using Wilder smoothing.


---

Attributes

Variable	Type	Description

period	int	ATR period
atr	double	Current ATR
count	int	Warmup counter
initialized	bool	ATR ready state



---

Methods

Constructor

ATR(int p);


---

update()

Signature

double update(
    double high,
    double low,
    double prevClose
);


---

Formula

True Range

TR = \max\left( high-low, |high-prevClose|, |low-prevClose| \right)

Wilder ATR

ATR_t = \frac{ATR_{t-1}(n-1)+TR_t}{n}

---

Regime Formula

TrendStrength = \frac{|FastMA - SlowMA|}{Price}


---

Regime Logic

TRENDING:
    trendStrength > minTrendStrength
    AND
    ATR > minATR

RANGING:
    otherwise

4.6 Risk Management Module

Responsibility

Controls:

Position sizing

Drawdown protection

ATR stop sizing



---

Risk Parameters

Parameter	Value

Risk Per Trade	1%
Max Drawdown	10%
Stop Multiplier	2 × ATR
Target Multiplier	4 × ATR



---

Position Sizing Formula

PositionSize = \frac{RiskAmount}{StopDistance}

Where:

RiskAmount = Equity × RiskPerTrade
StopDistance = ATR × 2


---

4.7 Trade Execution Engine

Responsibility

Simulates order execution.


---

Entry Conditions

BUY if:
    - No active position
    - Cooldown passed
    - FastMA > SlowMA
    - Momentum positive
    - Market regime = TRENDING


---

Exit Conditions

SELL if:
    - Price <= stop loss
    OR
    - Price >= take profit
    OR
    - FastMA < SlowMA

---------------------------------------------------------------------------------------------------

Signal logic — biggest upgrade

The original had one signal: fast MA > slow MA + momentum. That's extremely noisy and prone to false entries in sideways markets. The new bot uses a confluent scoring system — 4 independent indicators each cast a vote (-1 or +1), and a trade only fires when at least 2 agree:

EMA crossover (9/21 instead of SMA 5/20 — EMAs react faster to recent price)
RSI 14 — catches overbought/oversold conditions the MA alone misses
Bollinger %B — measures where price sits within its volatility envelope
Momentum vs ATR — normalized so it's meaningful regardless of the stock's price level

Position management — second biggest

Added a trailing stop that ratchets up as price rises, locking in profit
Changed to a 3:1 reward/risk ratio (take profit = 3× stop distance) vs the original's 2× stop and 4× target (those weren't matched to each other properly)
Position sizing still uses ATR-based volatility, but now won't fire until all indicators have warmed up (indicatorsReady flag)

Real OHLC from the API

The original set high == low == price, making ATR measure only tick-to-tick gaps (nearly useless). The new bot extracts dayHigh, dayLow, and prevClose from the same Yahoo Finance response — ATR is now a real volatility measure.

Robustness

SIGINT/SIGTERM handler for clean shutdown on Ctrl+C
Symbol configurable via argv[1] (./trading_bot TSLA)
indicatorsReady gate — no trades during warmup (original could trade on tick 1 with no data)
Trade log with PnL, win rate, and final equity summary printed on exit
